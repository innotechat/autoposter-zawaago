# Phase 2 — Production Hardening

## Scope

This phase hardens the verified Zawaago Autoposter without changing the already-verified Facebook publishing behavior.

### Verified baseline
- Zawaago text publishing: verified
- Zawaago image publishing: verified
- InnoTech text publishing: verified
- InnoTech image publishing: verified
- Selected Page IDs are configured
- Dedicated Page tokens are configured in Cloudflare secrets
- R2 image storage is connected
- Cloudflare Git deployment is working

## Phase 2 execution order

1. **Facebook token safety**
   - Use only `FB_TOKEN_ZAWAAGO` for Zawaago.
   - Use only `FB_TOKEN_INNOTECH` for InnoTech.
   - Remove the legacy shared `FB_TOKEN` publishing fallback.
   - Do not expose tokens in API responses, logs, errors, or UI.
   - Validate selected Page configuration before publishing.
   - Return safe, actionable Facebook errors without echoing credentials.

2. **Publish reliability**
   - Validate caption/image inputs.
   - Validate the public image URL before sending it to Facebook.
   - Normalize Facebook success responses.
   - Capture publish status and Facebook post ID for future history storage.

3. **Image/R2 pipeline hardening**
   - Validate generated bytes and content type.
   - Handle failed/partial R2 writes.
   - Keep generated asset URLs stable and cache-safe.
   - Prepare asset metadata for Gallery/Post History.

4. **Image Gallery**
   - Generated images grouped by brand/page.
   - Preview, reuse, regenerate, and publish actions.
   - Prepare archive/delete lifecycle without breaking published assets.

5. **Creative Studio UX**
   - Organize the workflow as:
     `BRAND → CONTENT → CREATIVE → GENERATE → REVIEW → PUBLISH`
   - Keep generation progress, errors, preview, editing, and publish state clear.

6. **Real brand logos**
   - Use uploaded Zawaago/InnoTech SVG/PNG assets.
   - Overlay the real logo after image generation.
   - Do not rely on image AI to render the logo.

7. **Post History**
   - Lifecycle: `Draft → Generated → Reviewed → Published`
   - Record Page, caption, image, timestamps, Facebook Post ID, status, and error.

8. **Multi-page-ready architecture**
   - Keep Page configuration data-driven.
   - Do not add new Pages in this phase.
   - Future Pages can be added without duplicating publishing logic.

## Security invariants

- A selected Page must never publish using another Page's dedicated token.
- A missing dedicated token must fail closed.
- `FB_TOKEN` is legacy compatibility only and must not be used for production publishing after Phase 2 token hardening.
- Secrets must remain Cloudflare encrypted secrets.
- No access token may appear in client responses or diagnostic output.

## Completion gate

Phase 2 is complete only when the hardened branch passes build/type checks and both existing Pages are re-tested for text and image publishing after the token-safety changes.
